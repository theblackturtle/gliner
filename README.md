# GLiNER PII Detection (Rust)

Rust-native HTTP service and CLI for detecting Personally Identifiable Information (PII) with GLiNER models.

## Highlights

- Chunked + batched inference for large files
- Label profiles for default, extended, private conversation, and log telemetry detection
- Auto-selects CPU or CUDA at runtime (falls back gracefully)
- JSON APIs and terminal UI parity with the former Python tools

## Prerequisites

- Rust toolchain (1.75 or later)  
- Optional: [uv](https://github.com/astral-sh/uv) + Python for exporting GLiNER checkpoints to ONNX

## Export the Model to ONNX

```bash
# Export the default model and tokenizer into ./models
uv run scripts/export_gliner_onnx.py \
  --model urchade/gliner_small-v2.1 \
  --output models
```

The directory must contain at least:

- `*.onnx` — the exported model
- `*_tokenizer/tokenizer.json` — tokenizer definition
- `*_tokenizer/config.json` — label metadata (generated by the exporter)

## Build & Install

```bash
# Build once
cargo build --release

# Or install the binaries to ~/.cargo/bin
cargo install --path .
```

Two executables are produced:

- `gliner-server` — Axum-based HTTP server
- `gliner-client` — CLI for interacting with the server

## Run the Server

```bash
# From source
cargo run --bin gliner-server -- \
  --artifacts models \
  --host 0.0.0.0 \
  --port 8000

# If installed via cargo install
gliner-server --artifacts /path/to/models
```

Key options:

| Flag | Description |
| ---- | ----------- |
| `--artifacts <DIR>` | Directory containing the ONNX model + tokenizer assets |
| `--threshold <float>` | Base confidence threshold (default `0.3`) |
| `--chunk-size <int>` | Characters per chunk (default `8000`) |
| `--batch-size <int>` | Chunks processed concurrently (default `8`) |
| `--max-workers <int>` | Directory scan worker cap (auto by default) |
| `--max-file-size <float>` | Maximum file size in MB (default `50`) |
| `--label-profile <name>` | `default`, `extended`, `private_conversation`, `log_intelligence` |
| `--disable-filters` | Disable false-positive filtering heuristics |

Health and info endpoints are exposed at:

- `GET /api/v1/health`
- `GET /api/v1/info`
- `POST /api/v1/scan/path`
- `POST /api/v1/scan/upload`

## CLI Usage

```bash
# Health check
gliner-client --server http://localhost:8000 health

# Inspect server configuration
gliner-client info

# Scan a path with extra log + conversation labels
gliner-client scan-path /var/log/app \
  --log-detection \
  --private-conversation \
  --threshold 0.5 \
  --output results.json
```

Useful flags for `scan-path`:

| Flag | Effect |
| ---- | ------ |
| `--labels person,email` | Custom label list (overrides profiles) |
| `--label-profile extended` | Select a predefined label profile |
| `--extended-labels` | Add the extended PII pack |
| `--private-conversation` | Add conversation leakage labels |
| `--log-detection` | Add log/telemetry leakage labels |
| `--no-recursive` | Disable directory recursion |
| `--disable-filtering` | Disable false-positive filter heuristics |
| `--show-all` | Display files even when no PII is detected |

## Project Layout

```
gliner/
├── Cargo.toml
├── models/                  # ONNX assets (exported separately)
├── scripts/export_gliner_onnx.py
├── src/
│   ├── bin/
│   │   ├── client.rs        # CLI entrypoint
│   │   └── server.rs        # HTTP server entrypoint
│   ├── labels.rs            # Label packs and profiles
│   ├── scanner/             # Core inference engine
│   ├── settings.rs          # Model + scanner configuration
│   └── types.rs             # Shared request/response types
└── target/                  # Cargo build artifacts
```
