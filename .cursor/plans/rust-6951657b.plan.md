# Rust Port Roadmap

1. Baseline & Model Export

- Audit `scanner.py`/`server.py`/`client.py` behaviour and config defaults.
- Add a conversion utility (e.g. `scripts/export_gliner_onnx.py`) to export the selected GLiNER checkpoint to ONNX plus tokenizer assets for Rust.
- Document required runtime assets (`model.onnx`, tokenizer JSON) and layout under a new `models/` directory.

2. Core Rust Library (`src/lib.rs`)

- Define a `pii_scanner` module encapsulating chunking, batching, and false-positive filters mirrored from Python.
- Integrate Hugging Face `tokenizers` crate and `ort` (ONNX Runtime) bindings for inference on CPU/GPU with device auto-detect.
- Recreate `PII_LABELS`, `EXTENDED_PII_LABELS`, and file extension filters in Rust constants.

3. Server Binary (`src/bin/server.rs`)

- Implement FastAPI-equivalent HTTP API using `axum` + `tokio`, wiring to the Rust scanner.
- Support upload scanning (multipart temp files) and filesystem path scanning with configurable thresholds, chunk sizes, worker pools, and CORS settings.
- Preserve health/info endpoints and CLI argument parsing via `clap`, including graceful shutdown signals.

4. Client Binary (`src/bin/client.rs`)

- Port the CLI with `clap` commands (`health`, `info`, `scan-path`) using `reqwest` and rich-style terminal output via `console`/`indicatif`.
- Match options (labels, extended labels, thresholds, output file) and tree-style result rendering; reuse shared response structs via a `shared` module.

5. Parity Validation & Packaging

- Implement integration/unit tests (e.g. sample text fixtures) to compare Rust scanner output against Python reference for key paths.
- Configure build artifacts (`Cargo.toml`, feature flags for CUDA/MPS, release profiles) and update the top-level README with Rust usage instructions.
